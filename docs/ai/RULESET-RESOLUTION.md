# Typed ruleset registry and source selection

Patch B of #53. This is a bounded content-resolution contract, not a combat or gameplay evaluator. The existing stat-core.js preview evaluator remains independent and unchanged. The original CC0-authored numerical defaults are suggestions, not official compatibility claims.

The optional host-selected smi-ruleset-registry/1 vocabulary defines versioned modules, properties, units, accepted value kinds, operation role (base/add/multiply/policy), numeric bounds and named proportional bases. The initial registry is rulesets/smi-core-v1.json. A host may supply its own validated registry; no globally activated ruleset. The existing manifest validator accepts syntactically valid custom profiles without requiring this particular registry. Semantic validation occurs when a host explicitly selects modules using resolveContributors. No unknown selected module or unsupported selected property is silently interpreted.

## Proportion

A typed concept value can be {"kind":"proportion","fraction":0.08,"basis":"target.health.max","rounding":"floor","unit":"hp","cap":30}. This means a magnitude derived from 8% of the specified host-provided basis. The eventual evaluator must compute the fraction, apply the optional upper cap, then round (nearest means nonnegative ties round upward), and enforce the property range. It must reject unavailable, negative or incompatible basis values, not treat unknown as zero. Rounding none permits fractional magnitudes. Fraction 0..10, optional cap 0..1e9; these are initial bounded contract choices. The planner validates the basis unit and explicit rounding, but does not calculate a result or read host state.

## Contributor selection

Call VisualAtlasCollections.resolveContributors(registry, contributors, rulesets, selections, overrides). Contributors have id, role, concept and optional archive_sha256 (caller provenance, not independently verified by this helper). The same concept may participate through different source IDs. A character, weapon, ability, attack-animation concept and temporary effect may all supply values. The host selects exact module versions. Missing optional profiles on an individual contributor are skipped; unused selected modules are reported. Values with the same property key are alternatives, not automatically added even if equal. Choose one source+module explicitly via selections, or supply an application override instead; simultaneous selection and override of the same key is rejected. Unselected single candidates are returned, with provenance. Override can choose another kind allowed for the property while retaining its registered unit. Modifier properties such as attack.damage.add and attack.damage.multiplier are separate typed proposals; their application is up to host policy. No automatic stacking or global source priority. If any conflict remains the result has ok:false, values:null and all candidates for diagnosis. The original concept stays unchanged. No random draws, timers, action costs or mutations are performed. Selection does not prove required action properties exist; host must validate actual action requirements.

Native animation timing remains authored in the visual asset (frame durations/FPS/sequence duration). A suggested attack.duration is a gameplay property, not the native animation length. A host may time-scale playback or schedule it independently. A visual marker never authorizes damage. Future action transaction/event contracts must guarantee idempotence even if an animation loops, is missing or is replayed.

The single-concept resolveDefaults helper from #51 retains its original strict selection semantics for compatibility. Existing stat_profiles and visual state sets are unchanged. Registry, typed value and resolver validation share the collection core; no second combat engine. Later milestones will extend the graph, state projection, transaction and provider contracts, including exact versioned concept locators. This patch does not implement state conditions, actual proportion arithmetic, runtime loading, 3D or a UI editor.
